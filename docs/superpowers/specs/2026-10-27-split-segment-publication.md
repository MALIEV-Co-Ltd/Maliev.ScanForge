# M2 split cutter and segment publication parity

The Split mesh GUI has an infinite-plane path for transient fitted plane objects, but public MCP binds only their bounded display mesh. Current plane producers persist planeFrame instead of transient fit metadata, which project loading drops, so both actual reopened paths currently miss the authoritative plane. Shared component extraction/split result publication also differs: GUI hides its source and selects the new mesh, MCP leaves the source visible/selected, and GUI does not own source visibility in model history. Earlier component lifecycle evidence checked geometry and owners but did not establish visibility/selection parity.

Use one split-cutter binder in GUI/MCP: `kind:plane` objects use their persisted planeFrame (or legacy transient fit) as an infinite plane, ordinary mesh cutters remain finite, open/closed solids retain existing algorithms. Filter/reject non-triangle cutters through one predicate. Explicit operation plane parameters remain authoritative. No native geometry algorithm changes.

Use one segment publication helper for GUI/MCP outputs, including component extraction and generic segmentation. Validate nonempty facet output, retain raw source and cutter buffers, create independent visible meshes with the GUI's normal part appearance, preserve classification by original result index, hide the source and select the first created owner. Canonical new names use the existing MCP source-name/segment-index form. Do not inherit exact/parametric/construction identities. Return one model-history transaction owning source visibility via `modelVisibilityFor`, so Undo restores the source and Redo hides it without altering unrelated display choices. All-empty output fails atomically.

Retain locks, cancellation, request/revision guards, history and persistence contracts. Existing tool parameters express the behavior; document default visibility/selection/appearance and plane binding, with current discovery descriptions. Prove actual failing unit/browser cases, then exact GUI/MCP geometry/state, independent area conservation, raw source/cutter identity, undo/redo, cancellation and binary reopen on plane, finite/open, convex/concave closed controls. Refresh component extraction lifecycle with visibility/selection assertions. Native input/settings/output gates remain open and separate.

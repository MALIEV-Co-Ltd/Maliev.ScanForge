## Large-file capacity

There is no application file byte, triangle-count, object-count or native-shape-count cap. Computational parameters such as fitting samples, control-grid size and iteration counts are bounded independently of file size. A 200,000,084-byte binary STL with four million triangles was rendered in prior browser validation. A 1,100,000,084-byte binary STL with 22 million triangles passed the streaming parser in Node, using an actual on-disk fixture; its full-resolution browser rendering remains unverified because the 6,144 MiB guard did not admit it. The same real on-disk source also passed browser import/render in explicit bounded-preview mode: every source record was read and validated, and 250,000 triangles were imported into a 9 MB position buffer. Measurements, edits, project saving and exports operate on that sample; the complete source geometry is not retained by preview mode. Neither proves unlimited capacity.

Binary STL reads bounded chunks into a transferable Float32Array. GPU normals, worker copies for non-destructive processing, full topology Maps/adjacency and native CAD require additional memory. Topology processing of a gigabyte scan has not been verified. Import and processing workers support cancellation and finite lifetimes.

## Reconstruction evidence

See [FEATURE_EVIDENCE.md](FEATURE_EVIDENCE.md) for REA resource, procedure and string evidence. The observed native inventory does not recover UI handlers or establish the original modeling algorithms. Functional equivalence remains unverified. The implementations here use independently chosen NURBS least squares, numerical sketch constraints, spatial registration and mesh graph algorithms.

Bounded preview is an explicit Settings option for binary STL, independent of source size. Text formats are rejected in this mode before whole-file buffering. Full-resolution import remains the default. Source counts persist in project metadata and remain visible beside sampled geometry.

## Large-file capacity

There is no application file byte, triangle-count, object-count or native-shape-count cap. Computational parameters such as fitting samples, control-grid size and iteration counts are bounded independently of file size. A 200,000,084-byte binary STL with four million triangles was rendered in prior browser validation. A 1,100,000,084-byte binary STL with 22 million triangles passed the streaming parser in Node, using an actual on-disk fixture; its complete browser import/render was not run because the resource guard did not admit it. Neither proves unlimited capacity.

Binary STL reads bounded chunks into a transferable Float32Array. GPU normals, worker copies for non-destructive processing, full topology Maps/adjacency and native CAD require additional memory. Topology processing of a gigabyte scan has not been verified. Import and processing workers support cancellation and finite lifetimes.

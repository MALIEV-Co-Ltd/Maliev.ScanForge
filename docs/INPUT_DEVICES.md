# SpaceMouse input

A persistent **Connect SpaceMouse** control beside the viewer navigation button makes device access available on every ribbon tab without opening Settings. It shows permission needed, chooser pending, connected waiting for reports, or receiving motion. Once connected, the same control opens navigation preferences; Settings retains its connection and disconnect actions. The initial permission chooser requires a user click and cannot open automatically on load. The browser's device chooser grants permission. On page initialization, `restoreAuthorized()` reopens a supported motion interface already authorized for this origin through `getDevices()`; it never prompts or grants new permission. A supported browser must expose WebHID in a secure context (HTTPS or localhost). Unsupported browsers show an unavailable status. The application does not install drivers or connect to a vendor/cloud service.

Supported report layouts cover SpaceNavigator, SpaceMouse Pro, Compact, Wireless, Pro Wireless and the Universal Receiver. An allowlist restricts product/vendor IDs. Signed six-axis reports drive camera-relative translation and rotation about the orbit pivot. Device buttons map to fit/isometric views when present. Settings adjust translation/rotation speed, deadzone, dominant-axis mode and rotation lock. These preferences are session-local.

Split and combined input layouts, invalid/truncated reports, button rising edges, stale-input expiry, disconnect and permission/open races are covered by synthetic HID tests. Camera tests cover translation, orbit radius, finite inputs and elapsed-time bounds. Physical-device axis direction, driver interaction, receiver routing and browser permission behavior require real hardware testing and have not been verified. An installed emulator does not prove a physical device works.

Motion expires after 150 milliseconds without fresh reports. Background pages ignore motion; animation stops when there is no input. Disconnect, page exit and component cleanup remove listeners and close only connections opened by this controller.

Protocol decisions use the public [WebHID specification](https://hid.spec.whatwg.org/) and [3dmouse-hid device report inventory](https://github.com/hcrlab/3dmouse-hid). The implementation is independently authored. Browser/OS policies can restrict access to devices; unknown devices are rejected rather than decoded speculatively.

The continuation validation adds a combined synthetic workflow from explicit HID selection/open through six-axis reports, camera movement, button callbacks, stale expiry and disposal. It verifies software routing and resource release, not physical hardware. A fresh Windows PnP inventory on 12 October 2026 detected a healthy SpaceMouse Pro HID device (`046d:c62b`), replacing the earlier emulator-only inventory. This proves OS enumeration; browser permission, incoming physical reports and camera navigation remain separate validation steps.

HID chooser results may contain multiple interfaces for one physical device, as described by the [WebHID requestDevice contract](https://hid.spec.whatwg.org/#dom-hid-requestdevice). The controller selects a supported interface containing motion report IDs 1/2, skipping button-only interfaces. Device descriptors absent from synthetic fixtures retain the original allowlist fallback. Axis reports are accepted in split six-byte and combined twelve-byte packets. Connection status distinguishes an open device waiting for reports from the first successfully decoded motion report, and does not trigger UI updates on every packet. A waiting status alone does not prove navigation works. Permission belongs to the browser profile and exact origin; access granted in a different browser or port does not authorize this preview.

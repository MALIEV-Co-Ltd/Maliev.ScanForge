## Independent implementation specifications

These are **engineering design proposals**, not recovered algorithms. Each must become a tested feature before changing its status to implemented.

1. **Landmark and fine registration.** Represent paired landmarks by entity-local coordinates and preserve the original entity transform. Reject fewer than three non-collinear pairs. Compute a rigid least-squares transform with an independently chosen SVD/Kabsch implementation; present RMS/max residuals before applying it. Follow with optional bounded point-to-plane ICP using spatial indices, robust residual weighting, cancellation and convergence reporting. Test synthetic known transforms, noise, degeneracy and undo. Global registration requires a separate pose graph and cannot be claimed from a two-scan solver.
2. **Cone fitting and constrained primitives.** Fit selected triangle/point samples, excluding hidden regions, and report model parameters, residuals and degenerate input failures. Optimize a cone's axis, apex and half-angle with a robust nonlinear solver initialized independently. Support optional world/reference-axis and coincidence constraints with explicit units/tolerances; show the accuracy tradeoff before acceptance. Torus recovery is a separate optional design, not established by the supplied evidence. Test translated/rotated truncated cones, noisy outliers and near-cylinder degeneracy.
3. **Sections and constrained sketches.** Store a sketch plane as an orthonormal frame and transform section samples into that frame. Build a graph of lines/arcs/circles/splines plus construction geometry, coincidence/orientation/tangency/symmetry constraints and length/radius/angle dimensions. A solver must report remaining degrees of freedom and conflicting constraints, support incremental editing and serialize stable IDs. Keep fitting section samples separate from exact constraints. Validate with manufactured synthetic profiles, closed-wire topology, degenerate segments, conflict detection and reload.
4. **Revolve, loft and sweep.** Extend the CAD worker contract with explicit profile IDs, exact curve/axis definitions, angular or path extents and surface/solid mode. Validate wires and input references before OpenCascade construction; preserve exact BREP plus editable feature parameters. Revolve needs full/partial angle handling, caps for valid solids and useful diagnostics for profiles crossing the axis. Sweeps require frame/twist policies and self-intersection failures; lofts require ordered compatible sections. Test exact analytic volumes, STEP round trips and transactional failure behavior.
5. **Freeform surface recovery.** Keep editable quad topology, boundary ownership, symmetry and crease definitions distinct from the scan. Provide constrained closest-surface snapping with a distance tolerance and patch fit diagnostics. Convert into NURBS patches using an independently selected algorithm, report continuity at joins, and validate sewing and watertightness before solid export. Automatic surfacing, reliable topology selection and continuity reconstruction require substantial independent work; kernel tessellation or a best-fit primitive does not satisfy them.
6. **Mesh repair and large-file execution.** Use typed geometry buffers, asynchronous parsing and bounded temporary chunks without an arbitrary application-level byte threshold. Retain optional user-controlled display decimation while preserving source geometry. Make allocation failures, cancellation, progress and actual browser/WASM address-space constraints explicit. Repair algorithms must separately validate orientation, boundaries, connected components, decimation error and holes. A successful multi-hundred-megabyte import is evidence for that tested file and device, not unlimited browser memory.
7. **History and analysis.** Persist an independently designed feature DAG with stable entity references, parameter versions, suppressed-state handling and deterministic rebuild invalidation. Implement scan-to-scan/CAD nearest-distance maps with a spatial accelerator and a documented sign convention. Draft analysis requires a direction and surface normals; continuity inspection needs actual boundary/tangent evidence. Test persistence, deleted/suppressed dependencies, rebuild rollback and known geometric distance cases.

## Completion criteria

The subsequent reconstruction slice implements independently chosen rational tensor surfaces/projected least squares, line-sketch numerical constraints, mesh graph diagnostics/repair/normal segmentation, landmark registration and trimmed sampled point-to-point ICP. Exact kernel operations now include loft/sweep, edge treatments, offset/sewing and shell/thickening. These do not fulfill the broader design proposals above (notably patch networks, curved sketches, global registration and feature DAG rebuild). Current contracts and executed checks are in CAPABILITIES.md and VALIDATION.md.

REA 6.4.0 portable PE-resource inspection was repeated during this slice and returned the same resource evidence ID. Current provider capability discovery and native prerequisites were inspected without launching a duplicate native analysis session. Available memory remained below the prior approximately 7.7 GiB decompiler working set, so the failed budget was not lowered and native algorithm recovery remains unresolved. No application runtime or original handler was recovered by the new modeling implementation.

Full functional reconstruction remains incomplete. Before claiming broad equivalence, each documented workflow needs its input/output contract, numerical tolerances, invalid-input behavior, state/persistence effects and relevant automated/browser evidence. Complete function recovery and Windows runtime observation remain separate unresolved evidence lanes. No activation circumvention, proprietary assets, extracted text, recovered original source or undocumented private formats are included in the public implementation.

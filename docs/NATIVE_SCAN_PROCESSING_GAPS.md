## Cylindrical Unroll

The shared implementation now narrows radial coordinates to Float32 before sqrt/acos/sign calculation. It removes facets touching angular quadrants zero and three, rechecks a removed slot after replacing it with the current last facet, and emits repeated copies with Float32 X translations. Positive offsets rotate the radial frame. The GUI and public MCP operation expose instances and create a separate owner by default; explicit replacement remains available. Resource admission, finite output, cancellation and representational-collapse checks remain enforced.

The manufactured 24-facet radius-2 mm open cylinder was imported with an exact cylindrical reference. Native exports at 0 degrees/one instance, 90 degrees/one instance and 0 degrees/two instances contain 22, 22 and 44 facets. The regression fixture `tests/fixtures/unroll-observed-cylinder.json` retains the source corners, settings, export digests and observed output corners. Arc/radial Float32 coordinates and full facet order match exactly. Axial coordinates differ by less than 1e-12 mm because the imported reference contributes a tiny frame rotation. This is a stated tolerance, not byte-identical full XYZ parity. A further 22-facet export uses a nonorigin center `[3,4,5]` and axis parallel to `[1,1,1]`; `tests/fixtures/unroll-observed-tilted-cylinder.json` and its regression also match exact arc/radial coordinates and order with the same axial tolerance. Its corrected exact reference retains an identity model placement; the initial reference with an extra placement transform was excluded.

The two directional globals are absent from archived file-backed raw ranges, but a fresh no-argument owned native process yielded stable startup triples `[1,0,0]` and `[0,1,0]` in two passive reads. [The capture and static instruction record](evidence/m2-unroll-startup-globals-20261027.json) pins the installed executable, the separately retained analysis image, bytes, resource limits and cleanup. A focused native candidate trace applies an inverse local frame to each source point, narrows two radial coordinates to Float32, normalizes them and then uses those globals in the angle and sign calculations. An independent decoder matched the mnemonics at all 507 recorded instruction starts after normalizing equivalent branch names. This trace does not prove the inferred function boundaries, every operand, the local-frame construction or that the globals remain unchanged during an Unroll command. GUI/export evidence resolves orientation for the observed +Z fixture; it does not bind every native cylinder frame. Production still constructs a deterministic world-projected tangent, and reference binding does not retain an imported cylinder's original tangent. Arbitrary tilted/imported reference conventions, cap/axis edge cases and complete native auxiliary sketch/frame publication remain open acceptance work.

A fresh reference-frame discrimination run rotates the exact cylinder's parametric seam tangent from +X to +Y while preserving its complete cylindrical side geometry, +Z axis and identity shape placement. The native 22-facet zero-degree/one-instance output matches every ordered coordinate byte of the original +X control. [The frame-control record](evidence/m2-unroll-frame-control-20261026.json) pins both exports and inputs. This establishes seam-tangent invariance for that control, rather than requiring the port to adopt the imported seam.

Using that actual STEP surface in the application exposed a different defect: fitting its display triangles perturbed the radius, producing first arc coordinate `0.5234062671661377` instead of the native `0.5235987901687622`. GUI and public MCP now bind `cylinderId` through the shared operation and read analytic parameters with the existing exact CAD kernel query. One cylinder face with optional planar caps is accepted; ambiguous or mixed curved bodies reject before geometry work. Explicit center/axis/radius requests remain supported. The new browser replay matches the retained native corner stream and preserves exact CAD through save/reopen, then actually reruns the GUI command. The native run also confirms creation of an auxiliary Sketch and hidden Roll frame; their complete publication remains an open gate. Its sketch IGES exports a vertical line at one circumference, from `[12.566370614,-1.665334537e-16,0]` to `[12.566370614,1,0]`.

A focused [frame-selection investigation](evidence/m2-unroll-frame-axis-selection-20261027.json) found two native candidates that select the least-aligned world axis, with X/Y/Z tie priority, before projecting into the radial plane. ScanForge previously chose X whenever the cylinder axis had an X component below 0.9, producing a different seam and angles on a manufactured Y-seed cylinder. The shared mesh and Roll-frame producer now use the same least-aligned selection. Existing native +Z and tilted controls and the new manufactured regression pass. On a manufactured Y-seed scan with an exact CAD reference, rendered GUI and public MCP produced identical full geometry, frame and sketch; source digests and Undo/Redo passed. The combined 5173 preview repeated the GUI/public-MCP geometry, frame, sketch and Undo/Redo checks with the same output digest. The final thirteen-batch production build passed with the updated MCP catalog. No native output has yet been captured for a Y- or Z-seed axis, and candidate boundaries and runtime reachability remain open. One construction-reference candidate reverses negative-Z directions; exact-CAD upstream sign handling and negative-Z parity require further native validation.

A [CAD-axis sign investigation](evidence/m2-unroll-cad-axis-sign-20261027.json) found a native extraction candidate that makes the largest-magnitude cylinder-axis component positive, with X/Y/Z tie priority, before frame construction. The shared exact-CAD Unroll binding now applies that convention without changing the CAD face; numeric and construction-cylinder directions keep their supplied signs. Four negative-direction binding regressions failed before the change, and 39 focused tests passed afterward. This behavior is inferred from static code: no negative-axis native Unroll export has established runtime equivalence, and the construction-reference sign path remains separately unverified.

## Average Mesh

The shared implementation now chooses the first scene-order mesh with the greatest facet count, queries other indexed surfaces in scene order against original source points, rejects open-boundary hits, and accumulates/divides through Float32 stores. Authored duplicate seam identities and unused base vertex records survive; derived normals are regenerated. Aggregate input carriers are admitted before worker cloning. Default publication creates and selects a new owner; explicit replacement and the singular target alias remain available.

A native GUI run imported the same two-facet base at Z=1 mm and one-facet references at Z=0 and Z=5 mm. The dialog showed 10.000 mm by default. Its exported two-facet output has every Z=2 mm, and its entire ordered corner stream equals production output. `tests/fixtures/average-observed-planes.json` records the exact input/output and export digest. This confirms the largest-input base and new-owner behavior for that run. Focused regressions additionally cover strict tolerance edges, open-boundary rejection, ordered Float32 accumulation, indexed seams, cancellation and buffer ownership. A second native two-mesh run places every base point outside an open reference rim but inside the 10 mm search radius. Its exported two-facet corner stream is unchanged and equals production output; `tests/fixtures/average-observed-open-rim.json` retains this boundary-rejection case. More difficult native query-tie and preparation cases remain open.

Three additional native exports now bind an equal-distance projection tie and its radius boundary. The base is imported first and tied with the reference at two facets. Reference faces at Z=+1/-1 mm yield every output Z=-0.5 mm at search tolerance10 mm, with either reference face order. At tolerance1 mm exactly, the native result preserves every base coordinate. `tests/fixtures/average-observed-ties.json` retains all three complete corner streams, input hashes and export hashes; production matches each exactly. These are finite native controls, not universal query/preparation equivalence.

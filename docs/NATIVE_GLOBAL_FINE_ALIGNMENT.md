# Native Global Fine Align

Global Fine Align is a distinct native workflow, not the existing coarse `mesh_process` registration kind `global`. Its ribbon entry remains planned while native geometry preparation, overlap queries and the complete multi-scan controller are being integrated. The numerical code below is internal groundwork; no new GUI command or MCP math tool is advertised.

## Verified local iteration

`scan-native-global-local.ts` reconstructs original `0x140aeb080`, retaining shared native rotation correction after composition. Its query boundary can await a bounded CPU worker without running competing pose updates. The caller owns query resources and cancellation/time limits.

Direct original execution covers 28 scenarios. The tests match every query-time Double pose and the final status, pose, mean, standard deviation and convergence/stability flags. Cases cover insufficient pairs, exact/noisy fits, inactive records, loss of more than twenty correspondences, complete loss of overlap, prior NaN statistics, and cancellation at entry or during a query. Geometry correspondence generation is controlled in these captures and is not claimed as native scene-query parity.

The local loop uses at most eight rigid fits. It reuses the previous query between iterations. A worsening mean with a sufficiently reduced match count rolls the pose back; the subtraction by twenty uses unsigned 32-bit arithmetic, including underflow for small counts. Error statistics and the current correspondence records retain the original rollback behavior. Convergence uses a strict Float32 tolerance; stability compares against the error at function entry, not against the immediately preceding iteration.

A machine-code detail matters: `COMISD` at `0x140aeb456` followed by `JBE` at `0x140aeb45e` terminates for an unordered relative-error ratio. JavaScript `ratio <= 0.001` would incorrectly continue on zero divided by zero. The port uses the equivalent negated greater-than condition. Complete loss of matches can leave native negative-NaN error statistics while retaining a finite pose. Those statistics are preserved internally; a future public response must represent unavailable diagnostics explicitly rather than silently reporting zero or declaring the workflow successful.

## Verified bulk point index and queries

`scan-native-global-point-index.ts` reconstructs the original bulk tree constructor, insertion/finalization, midpoint split, nearest query and radius query (`0x1405eb330`, `0x1405eb790`, `0x1405eb930`, `0x1405ec6d0`, `0x140aef5a0`, `0x140aef7b0`). The constructor parameter 48 is the points-per-leaf capacity. Bulk insertion preserves order and finalization splits high children first. Axis ties prefer Z, then Y, then X; coincident coordinates alternate between children. Original allocation-order node contents and linked point ordering are retained in flat typed arrays.

The nearest query uses Double arithmetic and strict comparison, retaining the first exact tie. The radius query has intentionally different arithmetic: Float32 query coordinates/subtractions, Float32 Y/Z squares, Double X square and accumulation, a Float32 squared radius, and Float32 stored distances. Comparisons happen before rounding stored distances. The sorted insertion branch removes one tail after 25 entries and shrinks the radius; the append branch does neither. Replacing this with a conventional capped nearest-neighbor search changes the original results, including a 26-entry result on an owner scan.

Query traversal is local to each call, rather than writing native node visit flags. A WeakMap reuses the index for the same immutable Float32 carrier and capacity. Geometry or eligibility changes require a new carrier; changing a pose does not require rebuilding a local-coordinate tree. This is preparation for bounded correspondence workers, not a claim that the complete global worker workflow is integrated.

## Verified correspondence branches and CPU workers

`scan-native-global-query.ts` connects the complete point-index, coordinate-transform, label/mask, neighborhood, plane-fit, projection and acceptance stages. Direct execution of original `0x140ae8c70` and the original multicore numeric callback `0x140ae9970` proves that these are different numerical branches, not two schedulers for one algorithm. The UI initializes the first configuration byte to 1; the controller clears it when fewer than two processors are available. On the recorded multicore host, the native UI therefore selects the per-target branch.

The serial `pooled-plane` branch fits one plane across label-matching neighbors gathered around the nearest vertex of each target. It accumulates transformed **source** normals, rounds the search radius to Float32 and accepts a projection only when its distance is strictly less than the greatest accepted nearest distance and absolute normal agreement is strictly greater than 0.95. The `target-average` branch uses each target's nearest record/normal, transforms them in Double, averages the target points and normalizes the sum of target normals. Its projection distance is compared against the incoming Double radius. The transformed source normal is not normalized in this branch. The original helper also supports CAD target references; those lists are empty in this scan-only reconstruction and replay, so CAD correspondence is not asserted.

Both paths compare label **words** with integer `CMP`, despite float-looking decompiler expressions. The signed-zero label case distinguishes that behavior. Assembly at `0x140ae9067`, `0x140ae9187` and `0x140ae8870` establishes the comparison boundary. Assembly also establishes that each target's complete transform is evaluated before adding it to the running sum; regrouping the sum into the transform causes one-bit differences on rotated scans. A vertex flag matching mask `0x1` is excluded when the target index is prepared, preserving original order and original source IDs. Mask rejection occurs after nearest lookup; it does not search again for another unmasked vertex. Cell/sample order and duplicate source samples remain intact.

The controlled replay includes 116 original query cases covering both branches, strict distance/normal thresholds, missing overlap, empty inputs, masks, labels, source/target poses, noisy patches, multiple targets and cell order. The native probes execute the per-cell numeric callback directly and merge in native cell order; they do not execute the original OS scheduler or application importer.

They initialize immutable geometry/indexes once per worker, keep query traversal local, send only new poses and source samples on later passes, and join contiguous sample batches in original order. ## Native scene preparation and sampling

`scan-native-global-scene.ts` reconstructs the common 4-by-8 angular grid, native normal-group merging, source classification and minimum size, expanded spatial bounds, first-representative occupancy, overlap flags and the two-level sampler. `scan-native-global-sampling.ts` retains the original per-cell CRT generator and quota rules. Sampling receives explicit clock inputs because native reseeding depends on environmental clock values. It does not replace those inputs with an unrelated random generator.

Common grouping chooses the first largest unprocessed bin above 50 points. Polar bins first absorb other azimuths in their own row, then neighboring rows/columns; previously processed bins may also contribute. The current target mean stays fixed during absorption. Empty bins retain stale means, which source classification still considers. Sources choose the first matching mean, discard groups below 100 points, and retain the common means rather than recomputing their own.

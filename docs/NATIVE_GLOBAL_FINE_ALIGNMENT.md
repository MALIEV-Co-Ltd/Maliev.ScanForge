# Native Global Fine Align

Global Fine Align is a distinct native workflow, not the existing coarse `mesh_process` registration kind `global`. Its ribbon entry remains planned while native geometry preparation, overlap queries and the complete multi-scan controller are being integrated. The numerical code below is internal groundwork; no new GUI command or MCP math tool is advertised.

## Verified rigid fitting

`scan-native-global-rigid-fit.ts` reconstructs original pair accumulator `0x140ae84b0` and rigid fit `0x140d60a80`. It preserves source/target sums, source-target covariance, reciprocal multiplication, the 4x4 Horn quaternion matrix, native quaternion-to-matrix expression grouping and translation arithmetic. The reported mean distance is the average Euclidean distance of the incoming pairs, before applying the fit; it is not a post-fit RMS. Fewer than three pairs return failure and identity. Degenerate inputs retain the original eigen tie behavior instead of introducing an independent degeneracy rule.

`scan-native-global-eigen.ts` reconstructs the original four-dimensional Householder/QL kernel `0x140892cd0`, preserving the absolute `2^-23` split threshold, iteration budget, stable hypotenuse helper and descending last-tie sorting. The established three-dimensional registration implementation is unchanged. REA Evidence:

## Verified local iteration

`scan-native-global-local.ts` reconstructs original `0x140aeb080`, retaining shared native rotation correction after composition. Its query boundary can await a bounded CPU worker without running competing pose updates. The caller owns query resources and cancellation/time limits.

Direct original execution covers 28 scenarios. The tests match every query-time Double pose and the final status, pose, mean, standard deviation and convergence/stability flags. Cases cover insufficient pairs, exact/noisy fits, inactive records, loss of more than twenty correspondences, complete loss of overlap, prior NaN statistics, and cancellation at entry or during a query. Geometry correspondence generation is controlled in these captures and is not claimed as native scene-query parity.

The local loop uses at most eight rigid fits. It reuses the previous query between iterations. A worsening mean with a sufficiently reduced match count rolls the pose back; the subtraction by twenty uses unsigned 32-bit arithmetic, including underflow for small counts. Error statistics and the current correspondence records retain the original rollback behavior. Convergence uses a strict Float32 tolerance; stability compares against the error at function entry, not against the immediately preceding iteration.

A machine-code detail matters: `COMISD` at `0x140aeb456` followed by `JBE` at `0x140aeb45e` terminates for an unordered relative-error ratio. JavaScript `ratio <= 0.001` would incorrectly continue on zero divided by zero. The port uses the equivalent negated greater-than condition. Complete loss of matches can leave native negative-NaN error statistics while retaining a finite pose. Those statistics are preserved internally; a future public response must represent unavailable diagnostics explicitly rather than silently reporting zero or declaring the workflow successful.

Local-loop REA Evidence: `ev_5418c90bcd936a703a2a32ce67e078734b58930b6340026c8a9dca8813f296dc`. Assembly Evidence: `ev_e87dd2804368444fb249e4bf72e4e190f8ae01e25f416c1246f8d46e433b3348`. ## Verified bulk point index and queries

`scan-native-global-point-index.ts` reconstructs the original bulk tree constructor, insertion/finalization, midpoint split, nearest query and radius query (`0x1405eb330`, `0x1405eb790`, `0x1405eb930`, `0x1405ec6d0`, `0x140aef5a0`, `0x140aef7b0`). The constructor parameter 48 is the points-per-leaf capacity. Bulk insertion preserves order and finalization splits high children first. Axis ties prefer Z, then Y, then X; coincident coordinates alternate between children. Original allocation-order node contents and linked point ordering are retained in flat typed arrays.

The nearest query uses Double arithmetic and strict comparison, retaining the first exact tie. The radius query has intentionally different arithmetic: Float32 query coordinates/subtractions, Float32 Y/Z squares, Double X square and accumulation, a Float32 squared radius, and Float32 stored distances. Comparisons happen before rounding stored distances. The sorted insertion branch removes one tail after 25 entries and shrinks the radius; the append branch does neither. Replacing this with a conventional capped nearest-neighbor search changes the original results, including a 26-entry result on an owner scan.

Query traversal is local to each call, rather than writing native node visit flags. A WeakMap reuses the index for the same immutable Float32 carrier and capacity. Geometry or eligibility changes require a new carrier; changing a pose does not require rebuilding a local-coordinate tree. This is preparation for bounded correspondence workers, not a claim that the complete global worker workflow is integrated.

The controlled original probe covers 20 tree cases and 300 nearest plus 300 radius calls. Full owner replay checks the source file and point-buffer digests, the complete native node/order hash, and 30 nearest/radius trials per scan. All three full PLY scans match: 140,113, 1,375,494 and 1,865,848 vertices (3,381,455 total), with 8,639, 84,531 and 113,735 tree nodes. These are complete original index executions, not sampled substitutes for the full tree. The optional owner replay is `SCANFORGE_ALIGNMENT_EXAMPLES=B:/temp/alignment-example-files` with `tests/scan-native-global-point-owner.test.ts`; it enforces the 3072 MiB admission guard.

The retained runtime probe binds the previously unidentified CRT import to `sqrtf`, confirmed by six adjacent export addresses sharing the same ASLR delta. Allocator, storage and current CRT import bindings are disclosed in the fixtures; numeric tree/query bodies execute from the immutable retained image. Native build timings include Python record-feeding overhead and must not be compared directly with JavaScript build timings as a speedup claim.

## Verified neighborhood plane fitting and fallback

`scan-native-global-plane.ts` reconstructs original `0x140a5a4a0`, including active-point filtering, three-point cross product, centroid, centered/uncentered moments, direction selection, scaled-row pivoted LU, candidate scoring, and orientation. The centered direction uses unsorted QL output and scores columns in reverse order by the L1 norm of the matrix-vector product. Candidate plane scores use mean absolute distance, not RMS. A score tie selects the linear candidate. Orientation sums all input normals, including inactive records. Defaults in the actual global query carrier are normal `[1,0,0]` and active 1; the fixtures also exercise inactive and custom-normal cases explicitly.

The existing three-dimensional QL solver gains an optional sorting flag; its default sorted behavior remains unchanged. `scan-native-jacobi-eigen.ts` implements the original maximum-off-diagonal fallback, first strict maximum, 1000-rotation limit, and optional last-tie descending sort. The native fallback calls the host CRT mode-3 trigonometric path. Using JavaScript `Math.sin`, `Math.cos` or `Math.atan2` introduces observable one-bit differences. The private bounded trigonometric kernels preserve the original polynomials, argument reduction, table corrections and explicit fused multiply-add instructions. `scan-native-fma.ts` performs exact finite-operand product/addition with one round-to-nearest/even using integer significands. This arithmetic is confined to the fallback; the primary QL path does not pay that cost. The sine/cosine API accepts only the half-pi range required by the original half-atan2 rotation.

Fifty-four complete original plane executions, 108 independent direction/linear-normal executions, and 432 independent QL/Jacobi executions (both sort modes) match the original output bytes. The corrected oracle follows output header pointers after native storage replacement and checks the dimensions and eigenvalue trace. Earlier captures that read stale preallocated value buffers are excluded. Transparent trig-call instrumentation on three cases reproduces all uninstrumented plane/algebra/eigen outputs and records the exact CRT calls for separate regression replay. Finite arithmetic coverage also includes signed zero, subnormals, overflow/cancellation and exponent extremes; invalid private-domain inputs are rejected explicitly.

## Verified correspondence branches and CPU workers

`scan-native-global-query.ts` connects the complete point-index, coordinate-transform, label/mask, neighborhood, plane-fit, projection and acceptance stages. Direct execution of original `0x140ae8c70` and the original multicore numeric callback `0x140ae9970` proves that these are different numerical branches, not two schedulers for one algorithm. The UI initializes the first configuration byte to 1; the controller clears it when fewer than two processors are available. On the recorded multicore host, the native UI therefore selects the per-target branch.

The serial `pooled-plane` branch fits one plane across label-matching neighbors gathered around the nearest vertex of each target. It accumulates transformed **source** normals, rounds the search radius to Float32 and accepts a projection only when its distance is strictly less than the greatest accepted nearest distance and absolute normal agreement is strictly greater than 0.95. The `target-average` branch uses each target's nearest record/normal, transforms them in Double, averages the target points and normalizes the sum of target normals. Its projection distance is compared against the incoming Double radius. The transformed source normal is not normalized in this branch. The original helper also supports CAD target references; those lists are empty in this scan-only reconstruction and replay, so CAD correspondence is not asserted.

Both paths compare label **words** with integer `CMP`, despite float-looking decompiler expressions. The signed-zero label case distinguishes that behavior. Assembly at `0x140ae9067`, `0x140ae9187` and `0x140ae8870` establishes the comparison boundary. Assembly also establishes that each target's complete transform is evaluated before adding it to the running sum; regrouping the sum into the transform causes one-bit differences on rotated scans. A vertex flag matching mask `0x1` is excluded when the target index is prepared, preserving original order and original source IDs. Mask rejection occurs after nearest lookup; it does not search again for another unmasked vertex. Cell/sample order and duplicate source samples remain intact.

The controlled replay includes 116 original query cases covering both branches, strict distance/normal thresholds, missing overlap, empty inputs, masks, labels, source/target poses, noisy patches, multiple targets and cell order. Full owner replay builds all three original point indexes once and reuses them across eight queries and changed poses. Every case uses the exact same explicit 1,000 source-vertex IDs in native and application execution, with every other complete scan as a target. All 2,653 accepted correspondence records match source ID, active state and all seven Double output values byte-for-byte. This is full target geometry with controlled source sampling, not the original scene/grid sampling or a complete global registration run. The native probes execute the per-cell numeric callback directly and merge in native cell order; they do not execute the original OS scheduler or application importer.

`scan-global-query-pool.ts` and `scan-global-query-worker.ts` provide one or two persistent physical CPU workers. They initialize immutable geometry/indexes once per worker, keep query traversal local, send only new poses and source samples on later passes, and join contiguous sample batches in original order. Physical worker count is independent of the selected numeric branch: memory admission or a one-worker request cannot silently switch the algorithm. Cross-origin-isolated browsers share immutable geometry buffers through `SharedArrayBuffer`; authored buffers remain intact. The pool uses a 512 MiB allocation estimate, a hardware/device-memory admission check, a 30-second request deadline and idle lease, and a 15-minute absolute lease. Abort, initialization failure, worker errors and expiry terminate the exact owned handles. Idle time starts after a completed request, so a long successful query does not immediately lose its caches.

The real isolated-browser replay verifies both modes on all eight full-owner cases, then repeats the default native mode through one physical worker and cancels a two-worker initialization. The two query workers and the single-worker replay each finish initialization once. All five created handles receive one initialization message and terminate; the final two are cancelled during initialization. Shared geometry is enabled, every original correspondence byte matches, and there are no browser errors. The fresh run with the corrected frame sampler took 1,567.57 ms to initialize, with a 16.68 ms median and 16.745 ms maximum frame interval. Subsequent default-branch queries took 5.37, 4.86 and 5.36 ms; its first query took 34.03 ms. These are local browser stage measurements, not a native-versus-JavaScript speedup or whole-registration timing claim. Sanitized results are retained in [the worker evidence](evidence/global-fine-correspondence-workers.json).

## Native scene preparation and sampling

`scan-native-global-scene.ts` reconstructs the common 4-by-8 angular grid, native normal-group merging, source classification and minimum size, expanded spatial bounds, first-representative occupancy, overlap flags and the two-level sampler. `scan-native-global-sampling.ts` retains the original per-cell CRT generator and quota rules. Sampling receives explicit clock inputs because native reseeding depends on environmental clock values. It does not replace those inputs with an unrelated random generator.

Common grouping chooses the first largest unprocessed bin above 50 points. Polar bins first absorb other azimuths in their own row, then neighboring rows/columns; previously processed bins may also contribute. The current target mean stays fixed during absorption. Empty bins retain stale means, which source classification still considers. Sources choose the first matching mean, discard groups below 100 points, and retain the common means rather than recomputing their own.

Function `0x140af08e0` writes each retained group's fixed RGB palette bytes into the vertex record at offsets `0x28` through `0x2a`, preserving byte `0x2b`. These packed words are the correspondence labels compared by the native queries. The port derives a separate labels array and preserves the authored positions, normals and original labels. Discarded groups retain their original words. The fixed palette is constructor state; it is independent of the controlled fixtures and owner geometry.

Spatial dimensions use Float32 extent subtraction followed by Double division and truncation. Cell sizes include the original 0.001 expansion. Occupancy retains the first point encountered in angular-cell order. Overlap checks one clamped cell in each other spatial grid, using the original expanded-bounds margin; it does not perform a neighborhood-radius search. Each eligible angular group's quota is the ceiling of budget divided by eligible groups. The inner spatial quota and correction are retained. A nominal budget of 1000 therefore selects 1352, 1518 and 1620 points from the three full owner PLY scans. Clamping those totals to 1000 would change the algorithm.

The controlled native probe executes the original constructor, insertion/merging, classification, RGB writer, spatial bounds/lookup, overlap marking and complete sampler. Thirteen complete controlled scenes cover minimum-size boundaries, polar/equatorial groups, no overlap, masks, reseeding, stable ordering and alpha preservation. The separate spatial probe covers 68 cases plus 12 CRT sequence/helper cases. The owner probe uses all 3,381,455 original Float32 points/normals from the three supplied PLY scans. Every common/source group membership hash, flags, mean bytes, label hash, spatial-layout bytes, overlap flag and selected point/order matches. Native allocator/container/iterator adapters are disclosed in the fixtures; the native importer, GUI and OS scheduler are not executed by these probes.

Local full-owner preparation measured 4093.15 ms in the JavaScript test process. This is a one-time preparation-stage measurement, not whole-registration latency or native speed parity. The background pipeline below now runs this stage in a bounded worker and retains prepared labels/samples through query pose updates. The private reconstruction is not yet wired into the GUI/MCP operation; it does not claim completed global registration.

## Connected preparation and correspondence workers

`scan-global-scene-client.ts` admits one disposable preparation worker at a time, with an estimated 512 MiB working-set limit, a two-minute main-thread deadline and abort handling. The worker has its own finite lease. Authored geometry is cloned without transfer; only newly derived labels and overlap flags transfer back. The response omits full group memberships and spatial working maps, so their memory dies with the worker. Missing browser worker support fails explicitly rather than blocking the UI; non-browser tests retain the synchronous numeric path. Malformed responses, worker errors, cancellation and timeout terminate the exact worker and release preparation admission.

`createPreparedGlobalQueryPool` passes the derived labels into the existing persistent correspondence pool, retaining native source sample IDs for changed poses. It filters source groups using native eligibility, rejects fewer than two eligible scans, defaults query masks to the preparation mask, and keeps numeric mode independent of physical worker count. Close, abort and query failure release the worker session. It does not run preparation again for each query or pose update.

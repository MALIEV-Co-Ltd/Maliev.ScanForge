# Native origin/reference alignment recovery

Origin/reference alignment remains incomplete and disabled. The existing main
Align callback performs an independently authored principal-axis operation;
that is not the recovered coordinate-system workflow.

Static mapped-PE resource inspection identifies the coordinate-system dialog
(template 481), its primary/secondary/tertiary feature selectors, plane-axis
assignments, flips, translation, Apply, Reset, CAD/all-feature scope and primitive
centering option. The constructor at `0x14053f410` binds this template; its
vtable message-map getter binds control callbacks. This is static routing
evidence, not native UI execution. Activation-prompt paths are excluded from
the implementation scope.

## Verified primary-direction numerical stage

`src/scan-native-datum-frame.ts` ports `0x1403a0fd0`. It constructs the two
remaining basis columns using the native cross-product choice and reciprocal
normalization. Ties use the native less-than-or-equal branch. A determinant error
greater than `2^-23` restores all twelve prior matrix values, including
translation. Translation is otherwise untouched.

The retained fixture executes the complete original frame helper and its
normalization instructions, with only the CRT square-root import rebound.
It contains 144 cases: three axis assignments, positive/negative standard axes,
zero and non-unit inputs, thirty oblique directions and thirty nonidentity
starting frames generated by the original quaternion helper. Tests compare
every returned double byte and verify input ownership. This does not capture
the complete dialog, feature picking, acceptance, history or mesh application.

## Verified plane-reference sequences

`src/scan-native-datum-plane.ts` ports the complete plane-reference constructor
and its secondary/tertiary acceptance and construction helpers. The retained
`alignment-datum-plane-native.json` fixture executes the original constructor
at `0x1403a0970` and captures all 232 bytes of frame state after every call.
Eighty sequences contain 236 steps, covering axis permutations, reversed and
oblique normals, zero normals, parallel references, repeated axis assignments,
and secondary/tertiary calls without initialization. Tests require exact return
acceptance and every state byte, including rejected states and signed zeros.
They also verify that the application helper does not mutate its input.

The secondary orientation uses opposite cross-product orders for the two
remaining axis assignments. Both orders preserve the native orientation;
substituting the reversed transverse vector flips two axes. Plane intersection,
projection, normalization and determinant rollback preserve native arithmetic
order and thresholds.

## Verified point-reference constructor

`nativeDatumPointReference` ports the original constructor at `0x1403a0cb0`.
Primary points reset the frame and set its translation. Secondary points
project onto the stored primary plane or line. Tertiary points project onto
the plane and then the stored line. Existing anchor flags reject redundant
point constraints without changing state.

`alignment-datum-point-native.json` retains 78 native executions across all
three stages and all prior plane/direction/point type combinations. Every setup
step calls the original constructor and retains its raw frame bytes. The point
test begins with that captured native state, independently of the application
plane port, and compares acceptance plus all returned state bytes. This proves
the point constructor on those mixed states, not the application direction
constructor or the full dialog. Input state remains unchanged.

Point constructor static Evidence:
`ev_b5a6eb468ae8ddbbeafaa1ab7af76b691c30bc18903f4f98de2f4b074c21bb91`.
The original direction acceptance, construction and fallback helpers have also
been recovered; their application port and runtime equivalence remain pending.

The numerical helpers are not yet connected to a public application action and
are not advertised in MCP discovery. Completing direction reference rules,
primitive reference conversion, preview/reset/acceptance and shared GUI/MCP
operation remains required before enabling coordinate-system alignment.

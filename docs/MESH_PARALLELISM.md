# Mesh processing parallelism

Screen selection uses two reusable workers for meshes with at least 100,000 triangles on devices reporting at least four logical CPUs. Devices reporting less than 8 GB memory use one worker. The pool is capped at two and a conservative 128 MiB geometry/BVH budget; very large meshes fall back to one. Preparation starts while choosing the selection tool. Workers expire after 60 seconds idle, are cancelled together on supersession or disposal, and queries have a 120-second timeout.

Each worker retains the whole visible mesh for cross-partition occlusion, but projects and tests only its assigned facet range. Masks are merged in original facet order after all workers finish. Partitioning changes neither visibility nor selection semantics. Small meshes retain one worker to avoid parallel startup overhead.

A local benchmark used the actual selection worker implementation in Node worker threads, 300,000 planar triangles, orthographic full-viewport rectangle, visibility enabled, four warm queries per configuration. Single-worker query times were 429, 460, 435 and 413 ms; two-worker times were 294, 257, 255 and 290 ms. Median latency decreased about 37%, with identical masks in every run. Initialization was 135 versus 261 ms. This is a synthetic benchmark on the current machine, not a guarantee for imported scans or browser hardware. The raw harness and results remain outside the repository.

The retained mesh-processing worker now receives source coordinates only on its first request. Subsequent requests reference its geometry key and send changing masks/targets; successful edits adopt the successor coordinates. Geometry replacement, cancellation and worker failure force a fresh transfer. This avoids a full source copy and transfer on every cached operation.

Selected smoothing uses two child CPU workers for at least 300,000 marked vertices on devices reporting four or more logical CPUs and at least 8 GB memory when available. An estimated 128 MiB incremental typed-array/copy budget caps admission. Smaller jobs use the same kernel on one worker. Ordered rings are cached by indexed connectivity. Each iteration reads immutable coordinates, computes disjoint targets and publishes only after both partitions finish. Jobs expire after 120 seconds, idle workers after 30 seconds; child workers also have an independent finite lease. Cancellation, supersession and transport failure retain the original geometry.

A benchmark using the actual pool and worker implementation in Node worker threads, closed disconnected tetrahedra, and two iterations measured warm median 195.4 ms serial versus 170.7 ms parallel at 300,000 marked vertices. All twelve cold/warm output comparisons were byte identical. At 100,000 marked vertices both medians were 51.5 ms, so those jobs remain serial. These are synthetic local measurements; browser transfer costs and imported scans need independent measurement.

Topology analysis, noise weight preparation, hole filling and defeature remain single-threaded within their dedicated worker. Their native numerical parity tests remain required. Separate workers for separate jobs are not multicore execution of one job.

## Avoiding repeated preparation

Scan Tools now forwards the geometry cache into noise and polygon reduction. Weld tolerances must match exactly before reuse. Noise reduction retains indexed connectivity and adopts its successor coordinates, so repeated edits avoid welding and adjacency construction. Selected vertices shared with unselected facets move consistently across incident facets. Polygon reduction changes connectivity and cannot retain the old adjacency as its successor. Scan Edit also constructs component/boundary inventory only when requested and expands smoothing output directly into a typed array.

A previous local 20,000-triangle sinusoidal grid benchmark measured 273 ms cold topology preparation, 117 ms cached noise reduction versus 256 ms uncached, and 74 ms for the next cached edit. Cached and uncached outputs were identical; warm edits emitted no welding stage. Those measurements cover the superseded conservative noise algorithm, not the integrated native kernel. Raw input, harness and results stay outside the repository.

## Acceleration acceptance gates

The extracted native octree query has a separate signed-result gate. The query port reproduces 33 executions of the original x64 query and triangle-distance instructions on caller-built nodes: ordered opposite-winding leaf entries, all midpoint-side combinations, forced upper-Z mode, missing preferred children, and strict search-radius exclusion. These captures validate traversal and signed winners, not native tree construction. The viewport comparison continues using its existing BVH until subdivision, child bounds and triangle overlap are independently executed and verified; matching absolute distances alone does not establish signed tie parity.

Measure cold preparation, warm kernel, diagnostics/output assembly, transfers and browser highlight latency independently. Record mesh size, selection size, hardware, worker count, repeated timings and correctness alongside every claimed gain. A warm synthetic result is not an imported-scan latency guarantee.

Selected smoothing partitions vertices, preserves ordered one-ring sums within each vertex, and synchronizes every iteration before publishing coordinates. Tests compare serial and partitioned output byte-for-byte on native boundary/disconnected-fan fixtures and irregular high-valence/sparse selections. Retain cancellation, bounded memory, size thresholds and a single-worker fallback. Do not duplicate object-rich topology in every worker.

Native Reduce Noise tracing identified a distinct correction-based kernel and a CPU task partition/join in its weight preparation. The application now uses that kernel: default one iteration, whole mesh and boundary smoothing enabled. The integrated operation matches every captured coordinate on the same 96-triangle source for whole-mesh iterations 1, 2 and 3 and selection-only iterations 1 and 3 with the same 16-facet mask, plus one whole-mesh iteration with boundary smoothing disabled. Float32 normal storage with a double-precision reciprocal is essential to this match. These fixture results do not establish parity for every mesh. Deviation measurement now reports the percentage of original vertices within the comparison threshold of the smoothed surface and does not limit the smoothing result. Immediate Smooth and defeature retain their existing native fixture gates.

The production Reduce Noise worker now has an asynchronous two-worker path. Each vertex's packed ring preserves the original facet/corner contribution order, including repeated boundary-edge contributions. Every iteration first joins all neighbor means, then joins all corrected coordinates before publication. Selection-only still prepares whole-mesh means; only marked vertices (including shared seams) receive corrections. Weight preparation remains serial to preserve Float32 normal accumulation. Small jobs avoid packing rings and use the existing serial kernel. Admission requires at least 300,000 vertices, four logical CPUs, 8 GB reported memory when available, and at most 128 MiB estimated additional copies. Jobs and child workers have 120-second expiry; workers close after 30 seconds idle. Cancellation discards incomplete coordinates; transport failure restarts the unchanged source on the serial kernel.

The source STL hash, retained native export hashes and 16 selected facet IDs were rechecked before integration. Partitioned results reproduce all captured coordinates for selection-only one/three iterations and whole-mesh one/two/three iterations, including boundary smoothing disabled. These are comparisons against retained native exports, not a new native UI capture.

A real Node worker-thread benchmark repeated the native annular source and 16/96-facet selection pattern across 300,032 vertices and 450,048 triangles. Warm medians were 661.4 ms serial versus 221.8 ms with two workers for one iteration, and 714.8 versus 349.5 ms for three iterations. Cold times were 640.3 versus 624.0 ms and 708.2 versus 416.1 ms respectively. All eight comparisons were byte identical. These measurements include weights, ring preparation and worker copies, but exclude welding, topology diagnostics, import and rendering; they compare the preceding serial kernel against the packed-ring worker implementation, not identical single- and double-worker ring implementations. Browser and real imported-scan latency remains a separate performance gate.

Noise normal preparation reuses three small typed scratch arrays instead of allocating point, edge and normal arrays per facet. Arithmetic order and precision are unchanged. A retained-topology Node benchmark on a 64,800-triangle sinusoidal grid measured a warm median of 73.0 ms before versus 40.1 ms after for one whole-mesh iteration with boundary smoothing enabled. Eight combinations of one/three iterations, whole/partial selection and boundary on/off matched the preceding kernel byte-for-byte across all 32 runs. This comparison establishes refactor equivalence, not additional native parity; the six native captures remain its numerical gate. Timings exclude topology construction, transfers and rendering.

The native deviation-color path is a separate parity requirement. Extraction of callback `0x14064bab0` shows original vertices queried against an acceleration structure of the smoothed preview, with a search radius of five times the comparison threshold. It counts successful samples whose absolute distance is at most the threshold and writes per-vertex colors; missing samples become RGB (50, 50, 50). Query helper `0x140213e90` chooses a strictly closer absolute signed-distance candidate, and `0x140563900` maps signed values through a configurable color ramp. The application now reproduces the magnitude/count metric with a BVH and reports the percentage within tolerance. The isolated original x64 triangle-distance routine was executed in a disposable helper, resolving only its CRT square-root import. The port matches all 492 samples exactly across all seven projection regions. Native-leaf exhaustive surface queries and the BVH match every distance magnitude and count on all six noise fixtures at two thresholds. This is numerical-kernel verification, not native UI capture: the desktop was locked. Adjacent-face equal-distance ties can differ in sign between an octree and BVH. Color defaults, sign tie ordering and the native rendered display remain unverified outside the captured numerical fixtures.

The extracted color ramp was separately executed from its original x64 instructions. The port matches 2,312 cases across two mutable palettes, including strict threshold boundaries and Float32 rounding. The captured palette is not established as the native default. The worker now returns per-corner RGB bytes only when deviation measurement is requested. It computes the ramp once per indexed vertex and then expands the bytes. The viewport uses a separate unlit overlay on original coordinates, converts sRGB through a 256-entry lookup, preserves hidden facet slots, and hides the smoothed object while comparison is shown. The tool can toggle the smoothed result; close, tool/selection/geometry changes and viewport disposal clear the overlay and release its scratch geometry/material. Geometry history retains only the smoothed result. Native-leaf distances plus the extracted color ramp match every published byte on all six captured noise cases at two thresholds; this does not establish the original UI palette default or all octree tie behavior.

GPU processing is not enabled. Any GPU experiment must pass native geometry comparison, device-loss/cancellation tests and end-to-end upload/readback benchmarks before producing committed geometry. The native correction kernel mixes double accumulation with Float32 storage; ordinary [WGSL floating-point types](https://www.w3.org/TR/WGSL/) are f32/f16, so equivalent output cannot be assumed. Sequential edge collapse and advancing-front repatching remain CPU operations pending separate algorithm verification.

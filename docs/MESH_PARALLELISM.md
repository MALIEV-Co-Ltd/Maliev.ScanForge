# Mesh processing parallelism

## Selected Reduce Noise correction verification

The selection-only numerical gate now covers iterations 1 through 5 on the same 96-facet input and 16 selected facet IDs. New two/four/five-iteration references execute the original x64 correction kernel `0x140a83270` from the SHA-verified mapped image, preserving its complete arithmetic and iteration loop. Allocation, object access, temporary masks, final normal refresh and release use isolated adapters. Weight values come from the production port, so this does not independently verify weight preparation on arbitrary meshes. Before accepting new references, the same harness reproduced every Float32 coordinate in the retained native UI one/three-iteration exports byte-for-byte. Native UI launch failed with access denied; these additional counts are numerical-kernel captures, not new UI exports.

The new fixtures include mapped-image and coordinate digests and their adapter limitations. Both synchronous and production asynchronous operations compare against them. Real CPU-thread tests also place connected selected neighborhoods across the two worker shards, verify each iteration finishes through both phase barriers without serial fallback, preserve unmarked/shared-seam behavior, and await worker exits. The existing production multicore path remains enabled under its memory and size admission rules; this extends its verified output gate without changing the smoothing formula or enabling GPU output.

The two-worker correction pass now copies unchanged coordinates with a typed-array operation and skips arithmetic for unmarked, isolated and boundary-locked vertices. Movable vertices retain the original neighbor order, double accumulation, Float32 publication and two barriers per iteration. The retained selection-only one/three-iteration native exports still match byte-for-byte in real CPU threads, including connected neighborhoods crossing shards and reused workers switching selection/boundary settings. A regression also checks that inactive coordinates preserve signed-zero bytes without reading invalid scratch means.

A bounded correction-phase benchmark on 300,000 vertices with 1,000 movable vertices measured medians of 4.91 ms before and 2.30 ms after, with identical bytes in all 12 comparisons. This excludes topology, means, worker transfer and rendering and establishes no end-to-end browser speedup.

The refreshed application was checked with the retained 96-facet source and exact 16 selected facet IDs. A three-iteration selection-only edit with boundary smoothing and deviation measurement enabled exported 864 coordinates matching the native export exactly. This small browser case uses the serial fallback; large admitted jobs use the separately tested two-worker path. The source and six native export hashes were rechecked. Additional iteration counts now have the numerical-kernel gate described above. Arbitrary imported meshes and full native UI behavior for those counts remain outside this verification.

Screen selection uses two reusable workers for meshes with at least 100,000 triangles on devices reporting at least four logical CPUs. Devices reporting less than 8 GB memory use one worker. The pool is capped at two and a conservative 128 MiB geometry/BVH budget; very large meshes fall back to one. Preparation starts while choosing the selection tool. Workers expire after 60 seconds idle, are cancelled together on supersession or disposal, and queries have a 120-second timeout.

Each worker retains the whole visible mesh for cross-partition occlusion, but projects and tests only its assigned facet range. Masks are merged in original facet order after all workers finish. Partitioning changes neither visibility nor selection semantics. Small meshes retain one worker to avoid parallel startup overhead.

A local benchmark used the actual selection worker implementation in Node worker threads, 300,000 planar triangles, orthographic full-viewport rectangle, visibility enabled, four warm queries per configuration. Single-worker query times were 429, 460, 435 and 413 ms; two-worker times were 294, 257, 255 and 290 ms. Median latency decreased about 37%, with identical masks in every run. Initialization was 135 versus 261 ms. This is a synthetic benchmark on the current machine, not a guarantee for imported scans or browser hardware. The raw harness and results remain outside the repository.

The retained mesh-processing worker now receives source coordinates only on its first request. Subsequent requests reference its geometry key and send changing masks/targets; successful edits adopt the successor coordinates. Geometry replacement, cancellation and worker failure force a fresh transfer. This avoids a full source copy and transfer on every cached operation.

Selected smoothing uses two child CPU workers for at least 300,000 marked vertices on devices reporting four or more logical CPUs and at least 8 GB memory when available. An estimated 128 MiB incremental typed-array/copy budget caps admission. Smaller jobs use the same kernel on one worker. Ordered rings are cached by indexed connectivity. Each iteration reads immutable coordinates, computes disjoint targets and publishes only after both partitions finish. Jobs expire after 120 seconds, idle workers after 30 seconds; child workers also have an independent finite lease. Cancellation, supersession and transport failure retain the original geometry.

A benchmark using the actual pool and worker implementation in Node worker threads, closed disconnected tetrahedra, and two iterations measured warm median 195.4 ms serial versus 170.7 ms parallel at 300,000 marked vertices. All twelve cold/warm output comparisons were byte identical. At 100,000 marked vertices both medians were 51.5 ms, so those jobs remain serial. These are synthetic local measurements; browser transfer costs and imported scans need independent measurement.

Topology analysis, noise weight preparation, hole filling and defeature remain single-threaded within their dedicated worker. Their native numerical parity tests remain required. Separate workers for separate jobs are not multicore execution of one job.

## Avoiding repeated preparation

Scan Tools now forwards the geometry cache into noise and polygon reduction. Weld tolerances must match exactly before reuse. Noise reduction retains indexed connectivity and adopts its successor coordinates, so repeated edits avoid welding and adjacency construction. Selected vertices shared with unselected facets move consistently across incident facets. Polygon reduction changes connectivity and cannot retain the old adjacency as its successor. Scan Edit also constructs component/boundary inventory only when requested and expands smoothing output directly into a typed array.

A previous local 20,000-triangle sinusoidal grid benchmark measured 273 ms cold topology preparation, 117 ms cached noise reduction versus 256 ms uncached, and 74 ms for the next cached edit. Cached and uncached outputs were identical; warm edits emitted no welding stage. Those measurements cover the superseded conservative noise algorithm, not the integrated native kernel. Raw input, harness and results stay outside the repository.

## Acceleration acceptance gates

### Native comparison construction dispatch

An experimental two-worker constructor now dispatches four ordered root octants per child and joins before publication. Each task caps generated descendants at 4,000 and cumulative subdivision memberships at 500,000; exceeding either retries the partitioned source through the serial constructor. Admission estimates triangle copies, overlapping membership arrays and bounded node results under 128 MiB, requires 80,000 triangles, four logical CPUs and at least 8 GB reported memory when available. Task timeout and worker expiry are 120 seconds. Cancellation releases both tasks and publishes no successor; transport failure and timeout release workers before serial retry. Real CPU-thread tests execute the bundled production child entry point and match every retained native tree and signed query, verify source immutability, and await worker exits. The asynchronous Reduce Noise comparison boundary uses the same query and color code as the synchronous path.

Automatic parallel construction remains disabled behind the explicit experimental argument to `prepareNoiseOctreeAsync`. A bounded Node benchmark on 80,000 sinusoidal grid triangles measured serial construction at 64.1, 59.5 and 58.9 ms versus 105.1, 99.3 and 84.9 ms with two workers. All three complete-tree hashes matched; both workers completed without fallback and exited after every run. Timings include packing, root partition, copies, construction and startup, excluding topology, smoothing, queries and rendering. Observed final process RSS was 135.3 MiB, not peak or total browser memory. This sample establishes no speed gain; automatic admission must wait for measured improvement through worker reuse or other workloads. Verified multicore smoothing remains enabled. Future integration must release retained smoothing copies before admitting construction workers and measure the combined phase budget.

The production constructor now separates Float32 triangle packing (`packNoiseOctree`), ordered root partitioning (`partitionNoiseRoot`) and independent child refinement (`refineNoiseOctant`). The native-tree regression completes octants in reverse order and verifies the complete tree, packed buffers, signed query winners and distances against every retained constructor case. This establishes task-order independence for those fixtures, not actual multicore execution, scheduler parity or a performance gain. Invalid task indices, missing root partitioning, invalid subdivision limits and pre-aborted tasks are separately checked.
